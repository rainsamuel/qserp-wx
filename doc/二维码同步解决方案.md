# 二维码同步解决方案

## 概述

本方案支持多种二维码格式的识别和查询：

1. **URL格式**（第三方同步）：`http://qr.ygyfnet.com/?o=91330000MA27U06H83&t=4&i=4220`
2. **资产编码**：本系统生成的资产编码
3. **卡片编号（KPBH）**：如 `1505032022031000682`
4. **JSON格式**：本系统生成的二维码内容

## 实施步骤

### 1. 数据库结构更新

首先执行字段添加脚本：

```bash
mysql -u用户名 -p密码 数据库名 < sql/sync_zcbq.sql
```

这个脚本会：
- 在 `biz_material` 表中添加 `sync_id`、`kpbh`、`sync_org_code`、`data_source` 字段
- 创建仓库映射表 `biz_warehouse_mapping`
- 创建查询视图 `v_material_query`

### 2. 数据导入

#### 方式一：使用Python脚本生成SQL（推荐）

```bash
cd doc
python3 parse_csv_to_sql.py
```

生成的SQL文件：`doc/import_data.sql`

然后执行：

```bash
mysql -u用户名 -p密码 数据库名 < doc/import_data.sql
```

#### 方式二：直接执行SQL导入

执行 `sql/import_zcbq_data.sql` 脚本：

```bash
mysql -u用户名 -p密码 数据库名 < sql/import_zcbq_data.sql
```

## 二维码解析逻辑

### URL格式解析

```
http://qr.ygyfnet.com/?o=91330000MA27U06H83&t=4&i=4220
```

解析结果：
- `syncId`: 4220（第三方系统ID）
- `orgCode`: 91330000MA27U06H83（组织编码）
- `t`: 4（类型）

### 查询优先级

1. 如果是URL格式，先按 `sync_id` + `sync_org_code` 查询
2. 如果未找到，尝试按 `asset_code` 查询
3. 如果未找到，尝试按 `kpbh` 查询
4. 如果未找到，尝试按 `material_code` 查询

## 测试用例

### 1. URL格式二维码

扫码内容：`http://qr.ygyfnet.com/?o=91330000MA27U06H83&t=4&i=4220`

查询接口：`GET /material/info/qrcode/http%3A%2F%2Fqr.ygyfnet.com%2F%3Fo%3D91330000MA27U06H83%26t%3D4%26i%3D4220`

### 2. 卡片编号查询

查询接口：`GET /material/info/kpbh/1505032022031000682`

### 3. 普通编码查询

查询接口：`GET /material/info/list?assetCode=1505032022031000682`

## 注意事项

1. **数据同步**：第三方同步的数据需要确保 `kpbh` 和 `sync_org_code` 字段正确填充

2. **仓库映射**：如果第三方系统的仓库ID与本地不同，需要在 `biz_warehouse_mapping` 表中配置映射关系

3. **索引优化**：已添加 `kpbh` 和 `sync_id` 索引，确保查询性能

4. **数据来源标识**：
   - `manual`：手动录入
   - `sync`：第三方同步
